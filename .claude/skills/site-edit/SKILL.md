# Editing the SHIVAS site

The site is hand-written HTML. There is no build and no templates, so every page carries its own copy of the header, mobile menu, footer and inline styles. Search before you edit. Change every copy.

## Ground rules
- Facts: never invent numbers, clients, projects, certificates or photos. If a fact is missing, write `[bracketed]` and add it to `docs/content-checklist.md`. No CE / ISO 9001 / EN 746 claims. Don't cite BS 729. Write **SHIVAS** in capitals.
- Keep the voice: short plain sentences, concrete, written for plant owners. No hype words. No emoji.
- Don't hand-edit `assets/library.js`. It is generated by the image-library tools (see `site/photos/README.md`). To use a picture, reference an existing file in `assets/library/`.
- Finish with the `site-check` skill (0 errors, no new warnings) and the `site-preview` skill on the pages you changed. After CSS, font or layout changes, also run the `site-audit` skill.
- Page head conventions on every page (keep them when copying a page):
  - `<link rel="preload" … noto-sans-latin.woff2>` and an inline `<style id="v52f">@font-face…</style>`. No Google Fonts.
  - Favicon links.
  - `<script defer src="…assets/site.js">`.
- New pictures: run `python3 tools/fix_img_sizes.py <page>`, then `python3 tools/responsive_images.py`.
- The home page quotes counts in its proof strip and links: products, 3D models, articles and photos. When you add a product, article, viewer or photos, update them. `check_site.py` warns when they're stale.

## Site-wide changes (phone, e-mail, address, nav, footer)
These appear in every page's header, mobile menu (`.v42m`), phone dock, enquiry section, footer and JSON-LD.
```bash
grep -rl "98109 20468\|919810920468\|+91-98109-20468" site --include=*.html | wc -l
```
Replace every format the number is written in (display, `tel:`, `wa.me/`, JSON-LD). Use a script for bulk edits, then re-run the grep to confirm nothing is left.

## Division pages: galvanizing.html, wire-drawing.html, reinplast.html
They are one app shown three ways (`data-page`). Make a shared edit in all three files with the same old→new text. A Python replace that asserts exactly one match per file is safest. Afterwards the site-check drift numbers must stay at about 71 and 103.
Text colours that fail contrast are fixed in the A11Y LAYER at the end of `assets/v39.css` (see `site-audit`). Don't add new light amber or teal text on white.

## Adding or editing a product page (items/)
1. Copy the closest existing item in the same division, for example `items/kettle.html` for galvanizing or `items/slm.html` for wire drawing.
2. Update `<title>` (`Name | SHIVAS Technology` or `| SHIVAS Reinplast`), the meta description, `<link rel="canonical" href="https://www.shivastechnology.com/items/<id>.html">`, `<html data-brand>`, and the `Product` (and `FAQPage`) JSON-LD.
3. Use pictures from `assets/library/` with `alt` and `loading="lazy"`, then run `python3 tools/fix_img_sizes.py items/<id>.html` to add each picture's real width/height. If there is no photo, use a `drawings.svg#<id>` line drawing.
4. Add a card to `items/index.html` (`<a class="mini" href="<id>.html" data-div="hdg|wire|rein">`), and links from the division page(s) and related items where they fit.
5. Add `<url><loc>https://www.shivastechnology.com/items/<id>.html</loc></url>` to `sitemap.xml`.

## Adding an article (blog/)
1. Copy an existing article in the same category, for example `blog/pickling-right.html`.
2. Update the title (`… | SHIVAS Articles`), meta description, canonical, and the `Article` JSON-LD (`headline`, `datePublished` as YYYY-MM-DD, `description`).
3. Add a `bcard` to `blog/index.html` with the right `data-cat`. To feature the article, swap the `bfeat` card. Update the article count wherever it appears (for example "All 25 articles" on `index.html`).
4. Add it to `sitemap.xml`. Link to it from 1–3 related item pages or articles.
5. Technical claims must be standard practice or come from the user. Cite ISO 1461 / ASTM A123 / IS 2629 / IS 4759 where relevant.

## Navigation (keep it identical everywhere)
- **Inner pages:** `<nav class="snav" aria-label="Site">` with Home, Products (`items/index.html`), 3D models, Calculators, Photos (`gallery.html`), Articles (`blog/index.html`), About and Contact, using paths relative to the page.
  - Put `aria-current="page"` on the current section.
  - Product pages mark Products; articles mark Articles; `calculator.html` marks Calculators.
- **Home header:** Products, 3D models, Calculators, Articles, About, Contact. Seven links overflow at 1240–1440 px.
- **Division pages:** in-page section links in `#nav .links`. The NAV LAYER in `v39.css` puts them on a second row from 900 px.
- **Quote button:** always "Get a quote" (on phones the dock says "Quote").

## Choosing hero and feature photos (accuracy)
- **Where the meaning comes from:**
  - The file name prefix tells you the product a photo is filed under, for example `line-fpl-…` means `items/line-fpl.html`, which is a *fumeless pickling line* and not a galvanizing plant. Check the product's `<title>` before using a photo anywhere else.
  - `-own-` photos have verified captions in `assets/library.js` (`config`). Use those words.
  - `-sup-` photos have no caption. Caption them with the product name, and nothing more specific.
- **Division heroes:** `.v61-hm` in `galvanizing.html`, `wire-drawing.html` and `reinplast.html`.
  - Only the visible division's main photo is `fetchpriority="high"`; the others are `loading="lazy"`.
  - Keep that per page.
- **Gaps:** where no accurate photo exists (for example the pultrusion line), don't substitute a related one. Add the gap to `docs/content-checklist.md`.

## Home page (index.html)
The sections are: banner slideshow (`.hbn`: slide 1 is the owner's banner from `assets/brand/` with transparent links over each tile, positioned in % of the image, so re-measure them if the banner changes; slides 2–7 are `assets/brand/slide-*.webp` with a caption and product link. Their `data-src`/`data-srcset` are filled in by the script after page load, to keep the phone LCP fast. The owner asked for no buttons (12 Nov 2026): it moves on its own every 3 s and can be swiped or dragged; after a manual scroll it waits 4 s. It also waits on hover, keyboard focus and when off screen; don't add controls back unless asked), hero (photo mosaic `.hmos`, buttons, proof strip `.hproof`), Start here, What we do, 3D models (`#models3d`), How we work, Calculators, Photos, Articles, About, Contact. Styles added in Nov 2026 live in `<style id="v60home">`. Mosaic photos use captions from `assets/library.js`. Use only `-own-` photos there.

## Enquiry form and tracking
- The home page form (`#qForm`) builds a WhatsApp message. It doesn't post anywhere. A real form backend (Formspree / Web3Forms / Apps Script) must deliver to SHIVAS addresses only. Ask the user before adding one.
- `assets/config.js` switches the visitor log, GA4 and company identification on or off. All three are empty now. To turn them on, use the `tracking-setup` skill.
