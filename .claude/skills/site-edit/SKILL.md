# Editing the SHIVAS site

The site is hand-written HTML. There is no build and no templates, so every page carries its own copy of the header, mobile menu, footer and inline styles. Search before you edit. Change every copy.

## Ground rules
- Facts: never invent numbers, clients, projects, certificates or photos. If a fact is missing, write `[bracketed]` and add it to `docs/content-checklist.md`. No CE / ISO 9001 / EN 746 claims. Don't cite BS 729. Write **SHIVAS** in capitals.
- Keep the voice: short plain sentences, concrete, written for plant owners. No hype words. No emoji.
- Don't hand-edit `assets/library.js`. It is generated by the image-library tools (see `site/photos/README.md`). To use a picture, reference an existing file in `assets/library/`.
- Finish with the `site-check` skill (0 errors, no new warnings) and the `site-preview` skill on the pages you changed.

## Site-wide changes (phone, e-mail, address, nav, footer)
These appear in every page's header, mobile menu (`.v42m`), phone dock, enquiry section, footer and JSON-LD.
```bash
grep -rl "98109 20468\|919810920468\|+91-98109-20468" site --include=*.html | wc -l
```
Replace every format the number is written in (display, `tel:`, `wa.me/`, JSON-LD). Use a script for bulk edits, then re-run the grep to confirm nothing is left.

## Division pages: galvanizing.html, wire-drawing.html, reinplast.html
They are one app shown three ways (`data-page`). Make a shared edit in all three files with the same old→new text. A Python replace that asserts exactly one match per file is safest. Afterwards the site-check drift numbers must stay at about 69 and 101.

## Adding or editing a product page (items/)
1. Copy the closest existing item in the same division, for example `items/kettle.html` for galvanizing or `items/slm.html` for wire drawing.
2. Update `<title>` (`Name | SHIVAS Technology` or `| SHIVAS Reinplast`), the meta description, `<link rel="canonical" href="https://www.shivastechnology.com/items/<id>.html">`, `<html data-brand>`, and the `Product` (and `FAQPage`) JSON-LD.
3. Use pictures from `assets/library/` with `alt` and `loading="lazy"`, then run `python3 tools/fix_img_sizes.py items/<id>.html` to add each picture's real width/height. If there is no photo, use a `drawings.svg#<id>` line drawing.
4. Add a card to `items/index.html` (`<a class="mini" href="<id>.html" data-div="hdg|wire|rein">`), and links from the division page(s) and related items where they fit.
5. Add `<url><loc>https://www.shivastechnology.com/items/<id>.html</loc></url>` to `sitemap.xml`.

## Adding an article (blog/)
1. Copy an existing article in the same category, for example `blog/pickling-right.html`.
2. Update the title (`… | SHIVAS Articles`), meta description, canonical, and the `Article` JSON-LD (`headline`, `datePublished` as YYYY-MM-DD, `description`).
3. Add a `bcard` to `blog/index.html` with the right `data-cat`. To feature the article, swap the `bfeat` card. Update the article count wherever it appears (for example "All 25 articles" on `index.html`).
4. Add it to `sitemap.xml`. Link to it from 1–3 related item pages or articles.
5. Technical claims must be standard practice or come from the user. Cite ISO 1461 / ASTM A123 / IS 2629 / IS 4759 where relevant.

## Enquiry form and tracking
- The home page form (`#qForm`) builds a WhatsApp message. It doesn't post anywhere. A real form backend (Formspree / Web3Forms / Apps Script) must deliver to SHIVAS addresses only. Ask the user before adding one.
- `assets/config.js` switches the visitor log, GA4 and company identification on or off. All three are empty now. Turning any on needs the user's go-ahead and a matching `privacy.html` (DPDP Act 2023).
